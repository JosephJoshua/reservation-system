# 订单与退款

本页的操作需要“财务”或“管理员”角色。

## 订单

“订单”页列出所有付款记录，包括学员在小程序中的微信支付，以及前台代约和售卖课时包时的线下收款。

<Shot src="img/admin/orders.webp" alt="订单" />

- 按下单日期、状态、类型（单次课、体验课、课时包）和支付方式筛选，或搜索学员；
- “金额”列显示已退金额；
- 点击学员姓名打开学员详情；
- 点击“导出”下载 CSV，用于对账。

### 支付异常

极少数情况下，微信支付通知的付款无法确认，例如实付金额与订单不符，或付款在系统确认前已在微信支付商户平台退回。系统不会确认这类订单，会释放占用的时段，并把订单标为“支付异常”：

1. 从“概览”待办中的“支付异常”进入，或在“订单”页勾选“支付异常待处理”。
2. 按订单号在微信支付商户平台核对这笔付款，需要时在商户平台退款。
3. 处理后点击“标为已处理”，填写处理说明（例如“已在商户平台全额退款”）并确认。说明会显示在订单上，并记入[操作记录](./action-log)。

有待处理的支付异常时，学员不能注销账号，小程序的预约详情会提示“付款异常，场馆会联系你处理”。导出的订单 CSV 中，“支付异常”列记录实付金额和处理说明。

## 退款

退款有以下几种来源：

- 学员在免费取消截止前取消微信支付的课程：**自动原路退款**，无需处理；
- 场馆或教练取消课程、小班课人数不足自动取消：微信支付的**自动全额原路退款**，前台收款的进入“待提交/待退还”，需要当面退还后确认；
- 学员申请退还课时包：**需要审核**；
- 前台收款的订单需要退款：**需要当面退还后确认**。

<Shot src="img/admin/refunds.webp" alt="退款" />

### 审核课时包退款

1. 在“退款”页筛选“待审核”，或从“概览”的待办进入。
2. 核对学员、课时包剩余节数和实付金额。“金额”列显示建议退款金额。
3. 点击“同意”，确认或修改退款金额后点击“确认退款”；或点击“拒绝”，填写拒绝原因（学员可见）。

<Shot src="img/admin/refund-approve.webp" alt="同意退款" />

建议金额 = 实付金额 − 已上课时按所上教练的单次价合计。同意后课时包作废：微信支付购买的，款项原路退回学员的微信；前台付款购买的，退款进入“待提交/待退还”，请当面退还后点击“已退还”。

如果这笔订单已经开票或正在申请开票，列表中会提示，请同时处理[发票](./invoices)。

### 线下退还

前台付款的订单不能原路退回。这类退款显示为“待提交/待退还”：

1. 把款项当面退还给学员。
2. 在列表中点击“已退还”并确认。

### 退款失败

微信支付退款失败时（例如商户余额不足），退款会显示在“退款失败”中。问题解决后点击“重试”。

重试前，系统会先向微信支付查询原退款。如果原退款其实已经成功或仍在处理，系统只更新状态，不会重复退款，操作记录中记为“退款状态已更新”。如果该订单的其他退款已经退完可退金额，重试会被拒绝。

如果一笔标为失败的退款后来实际成功，而这笔订单已另行退款，该退款会显示“与其他退款合计超过实付金额，请核对”的提示，请在商户平台核对。

如果微信支付提示退款异常（例如学员的银行卡已注销），退款会保持“退款中”，并显示“退款异常”提示。这类退款计入“概览”待办中的“退款异常”，也可在“退款”页勾选“退款异常”筛选。请在微信支付商户平台处理，处理完成后状态会自动更新。

| 状态 | 说明 |
| --- | --- |
| 待审核 | 学员申请的课时包退款，等待处理 |
| 待提交/待退还 | 前台付款的退款，等待当面退还 |
| 退款中 | 已提交微信支付，等待到账 |
| 已退款 | 退款完成 |
| 退款失败 | 微信支付退款没有成功，可重试 |
| 已拒绝 | 已拒绝学员的申请 |
